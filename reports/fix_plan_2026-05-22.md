### [1] ✅ SELL Break-Even Offset — risk_manager.py:163

- **الملف:** `risk/risk_manager.py` السطر 163
- **المشكلة:** الكود الخاطئ:
  ```python
  new_sl = round(entry + offset, 3)  # SL فوق entry لحماية صفقة البيع
  ```
  للصفقة **SELL** — مثال: Entry=1.1000، offset=0.0002
  - SL يُوضع عند 1.1002 (فوق entry)
  - عندما يرتفع السعر ليضرب SL عند 1.1002:
    - بِعنا عند 1.1000 واشترينا عند 1.1002
    - **خسارة 2 pip بدل التعادل** ❌

- **الإصلاح المطبّق:**
  ```python
  new_sl = round(entry - offset, 3)  # SL تحت entry بـ offset → ربح عند الضرب
  ```
  - SL يُوضع عند 1.0998 (تحت entry)
  - عندما يرتفع السعر ويضرب SL عند 1.0998:
    - بِعنا عند 1.1000 واشترينا عند 1.0998
    - **ربح 2 pip** ✅
  - SL لا يزال فوق السعر الحالي (الذي انخفض إلى 0.9900 مثلاً) → MT5 يقبله ✅

- **ملاحظة:** الإصلاح لا يُغيّر الحماية — SL لا يزال يمنع الخسارة الكبيرة؛ الفرق فقط في اتجاه الـ offset الذي كان يُعطي 2 pip في الاتجاه الخاطئ.
- **الحالة:** ✅ **طُبّق تلقائياً** (مدرج في PRD كأولوية + 2 يوم انتظار + خطأ منطقي مؤكد)

- **الملف:** `strategy/xauusd_signal.py:126`
- **المشكلة:** `_regime_check()` تستدعي yfinance API في **كل دورة 15 دقيقة**:
  - 24+ طلب HTTP في جلسة NY واحدة
  - عند فشل API → fail-open (جميع صفقات XAUUSD مسموحة بدون فلتر)
- **الإصلاح المقترح:**
  ```python
  def __init__(self, ...):
      self._regime_cache = None  # (result: bool, timestamp: float)

  def _regime_check(self) -> bool:
      import time as _t
      now = _t.time()
      if self._regime_cache and (now - self._regime_cache[1]) < 3600:
          return self._regime_cache[0]
      result = self._fetch_regime_live()
      self._regime_cache = (result, now)
      return result
  ```
- **الفائدة:** 24 طلب → 3 طلبات يومياً + استقرار عند انقطاع الشبكة
